# 具身前沿研究站设计说明

> 状态：已由 `2026-08-18-github-visual-research-station-design.md` 取代。本文保留第一、二阶段的历史设计依据；后续架构、视觉系统与部署决策以新规格为准。

## 1. 目标与边界

建设一个独立的具身智能研究站“具身前沿 · Embodied Frontier”，服务于个人研究沉淀、结构化知识检索和后续自动研究工作流。站点不依赖 CareerForge，不复制 `embodied-ai-learning` 的无许可证源码、视觉资产或内容，只借鉴其“内容优先、研究路线组织、证据标注”的信息架构思想。

事实源固定为仓库内 Markdown，Git 历史负责版本追溯。系统一次设计完整架构，按三个可独立验收的阶段顺序交付。

## 2. 已确认需求

- 阶段一：研究主页、专题导航、论文笔记、项目与学习路线。
- 阶段二：全文检索、组合筛选、模型/数据集对比、知识图谱。
- 阶段三：定时发现论文与新闻、AI 提取、证据标注、自动生成 PR，人工审核合并后才发布。
- 内容必须来自仓库 Markdown，不引入数据库作为内容事实源。
- 移动端优先，支持响应式布局、键盘操作、可访问性和 `prefers-reduced-motion`。
- 不使用首屏 WebGL、重型 HUD 或阻塞式开场动画。
- 站点初期公开只读；写入行为只发生在 Git/PR 工作流中。

## 3. 方案比较与决策

### 方案 A：VitePress 深度定制

优点是 Markdown 原生、文档路由和本地搜索成熟；缺点是做独立视觉和后续研究应用交互时容易把大量逻辑挤进主题层，参考站已经体现出这一维护风险。

### 方案 B：Astro + 内容集合

优点是静态性能好、内容模型清晰；缺点是当前工作区没有既有 Astro 基础，第二阶段的交互组件和部署适配需要额外建立约定。

### 方案 C：Vinext/React + 构建期 Markdown 内容层（采用）

优点是页面和内容层边界清晰，能够保持静态内容优先，同时为第二阶段图谱和第三阶段审核展示保留应用能力；可部署为 Cloudflare Worker 兼容产物。代价是需要自行建立 Markdown schema 和构建校验。

最终采用方案 C。第一阶段不启用数据库、账户系统或运行时 CMS，避免不必要复杂度。

## 4. 信息架构

### 全局导航

- 首页 `/`
- 论文 `/papers`
- 研究路线 `/roadmap`
- 项目 `/projects`
- 关于 `/about`

### 首页

首页按“研究判断”而不是功能堆叠组织：

1. 首屏：站点定位、VLA/WAM/Data & Eval 三条主线、主要入口。
2. 研究雷达：三条路线的当前问题、代表论文和进度。
3. 最新笔记：来自 Markdown 的最近更新。
4. 学习路线：基础、核心、前沿三个阶段。
5. 项目现场：展示正在做的评测、系统和复现工作。
6. 证据约定：明确 `verified`、`self-reported`、`unverified`。

### 论文详情

每篇论文独立路由 `/papers/[slug]`，页面内容来自 Markdown，并至少显示标题、日期、方向、标签、摘要、证据状态和来源链接。

## 5. 内容模型

Markdown 使用 YAML frontmatter。阶段一包含三类内容：

```yaml
---
title: "OpenVLA"
slug: "openvla"
date: "2024-06-13"
updated: "2026-08-18"
track: "VLA"
venue: "CoRL 2024"
status: "verified"
tags: [open-source, action-tokenization]
summary: "面向通用机器人操作的开源 VLA 基线。"
sources:
  - label: "Paper"
    url: "https://arxiv.org/abs/2406.09246"
---
```

允许的证据状态只有：

- `verified`：论文、官方项目页或独立来源可直接核验。
- `self-reported`：指标或结论仅来自作者/厂商自评。
- `unverified`：来源不足或口径尚未确认。

构建时必须校验必填字段、slug 唯一性、日期格式、证据状态和来源 URL。失败时阻断构建，不能把不完整内容发布出去。

## 6. 技术架构

```text
content/**/*.md
      ↓ Vite eager raw import + frontmatter parser
lib/content/*（schema、解析、排序、查询）
      ↓ typed records
Vinext React Server Components
      ↓
静态优先页面 + 少量客户端交互
      ↓
Cloudflare Worker compatible build
```

模块边界：

- `content/`：唯一内容事实源。
- `lib/content/`：解析、校验和查询，不包含 UI。
- `components/`：可复用展示组件，不直接读取文件。
- `app/`：路由与页面组合。
- `scripts/research/`：第三阶段发现、去重、提取和 PR 生成。
- `.github/workflows/`：构建检查与自动研究工作流。

## 7. 视觉系统

视觉方向为“研究编辑部 + 实验记录”，不采用赛博 HUD：

- 背景：暖白与深墨蓝双层纸面感。
- 主色：高对比钴蓝；强调色使用克制的橙红。
- 字体：系统中文无衬线作为正文，等宽字体用于编号、标签和证据状态。
- 图形：CSS 网格、细线、编号、实心状态点；不使用生成式装饰插图作为核心信息。
- 动效：只使用淡入、轻微位移和 hover 状态；在 reduced-motion 下关闭位移动画。
- 卡片保持平面化，优先清晰层级和触控面积，不做鼠标跟随倾斜。

## 8. 三阶段交付

### 阶段一：可发布研究站

- 完成所有一级路由和代表性 Markdown 内容。
- 首页从真实内容自动生成最新论文与研究状态。
- 完成移动端、桌面端、键盘焦点和 reduced-motion。
- 完成内容 schema 校验、构建测试、基础 SEO、sitemap/robots。

### 阶段二：知识探索能力

- 构建期生成全文索引，不把内容发送给第三方搜索服务。
- 浏览器端组合筛选：track、tag、year、venue、status。
- 模型和数据集采用独立 Markdown schema，生成可比较表格。
- 构建期从显式关系字段生成图谱 JSON；客户端按需加载图谱组件。
- 图谱必须提供列表等价视图，避免仅依赖视觉节点操作。

### 阶段三：自动研究与审核

- 定时工作流只写 `content/inbox/` 或新分支，不直接写主分支。
- 候选内容经过 URL 规范化、标题/arXiv ID 去重和来源可访问性检查。
- AI 输出必须匹配 JSON schema，再渲染为 Markdown。
- 每条结论保存 source URL、抓取时间、证据状态和生成模型信息。
- 工作流创建 PR，附新增/更新/跳过数量和校验报告。
- 主分支保护要求人工审核与构建检查通过；禁止机器人直接合并。

## 9. 错误处理与安全边界

- 单篇 Markdown 不合法：构建失败并输出文件路径与字段错误。
- 外部来源不可访问：候选保留为 `unverified`，不得自动提升为已核验。
- AI 返回格式错误：保存原始任务日志为短期 CI artifact，不创建内容 PR。
- 重复论文：以 DOI、arXiv ID、规范化 URL、标题指纹依次去重。
- API key 只存 GitHub Actions Secrets，网页构建产物不得包含密钥。
- Markdown 渲染禁止任意 HTML，外链统一带安全属性。

## 10. 性能与可访问性预算

- 首页首屏不加载图谱、地图、Three.js 或 WebGL。
- 阶段一自定义客户端 JavaScript 目标低于 80 KB gzip。
- 首屏核心内容在 360 px 宽度下无横向滚动。
- 所有交互目标最小 44 × 44 px。
- 颜色对比达到 WCAG AA；状态不能只靠颜色表达。
- 页面具备唯一 `h1`、跳转到正文链接、清晰 landmark 和可见焦点。

## 11. 验收与证据分层

- 源码审计：文件边界、Markdown schema、无复制资产、依赖清单。
- 构建通过：类型检查、内容校验、生产构建和渲染测试全部通过。
- 浏览器验证：代表路由在桌面/移动宽度可读，键盘可达，无阻塞错误。
- 部署：只有获得部署地址并进行线上 smoke 后才标记为已部署；本地构建不能替代部署证据。

## 12. 明确不做

- 第一阶段不做登录、收藏、评论、数据库和网页 CMS。
- 第一阶段不做完整知识图谱与自动抓取。
- 不直接搬运参考站代码、图片、品牌、文案或数据集。
- 不把 AI 生成内容未经审核直接发布。
