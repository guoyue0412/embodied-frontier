# GitHub-first 具身智能研究站视觉升级设计

## 1. 状态与目标

- 状态：已确认，待用户复核书面规格。
- 取代：`2026-08-18-embodied-frontier-design.md` 中关于 Vinext、Cloudflare Worker、禁用首屏 WebGL和克制静态视觉的决策。
- 目标：把现有“具身前沿”升级为由 GitHub 驱动、以仓库 Markdown 为事实源、具备高辨识度交互视觉的独立研究站。
- 原则：直接复用有明确许可证的上游组件；不复制许可证不明的参考站源码、内容、品牌或视觉资产。

## 2. 已确认范围

本轮设计覆盖：

1. GitHub 仓库、Pull Request、Actions、Pages 构成的开发与发布主干。
2. 从有许可证的上游直接集成互动背景、文字动画、3D 与知识图谱能力。
3. 首页、论文检索、模型/数据集对比、知识图谱和论文阅读页的视觉升级。
4. 桌面端、移动端、键盘操作、低性能设备和 `prefers-reduced-motion` 的等价体验。
5. 延续第三阶段“自动生成内容 PR、人工审核后发布”的内容治理方案。

本轮不包含用户账户、评论、收藏、数据库、在线 CMS 或未经审核的自动发布。

## 3. 参考站审计结论

参考站 `ZhuYun97/embodied-ai-learning` 在审计提交 `760997653b533dc4eb80b4f38a725f278314cd6d` 上使用 VitePress，并组合 Vue、Three.js、Cytoscape、Mermaid、Leaflet 和自定义主题组件。

已确认的实现模式包括：

- Canvas 点阵根据光标速度产生局部位移，并在空闲时停止动画帧。
- Three.js 网格与 DataTexture 驱动图片 UV 扭曲。
- GLTF 模型使用 PBR 贴图、环境光照、指针朝向和离屏停帧。
- Web Animations API 驱动字符重排。
- Cytoscape 和离线构建数据驱动论文关系图。
- `prefers-reduced-motion`、触屏静态回退、动态导入和资源清理用于控制性能风险。

参考仓库根目录未发现 LICENSE。根据 GitHub 的许可证说明，无许可证项目默认保留全部权利，因此只复用上述公开技术思想，不复制其源码或资产。

## 4. 技术方案比较

### A. 继续使用 Vinext/Worker

- 优点：当前页面和测试无需迁移。
- 缺点：当前构建目标是 Worker，而 GitHub Pages 只托管静态文件；需要维护第二套静态导出路径。
- 结论：不采用。它会让 GitHub Pages 成为附属部署，而不是系统主干。

### B. VitePress + Vue 深度主题

- 优点：最接近参考站，Markdown 与文档导航成熟。
- 缺点：高度定制后容易把行为、主题和数据逻辑集中到全局主题；不利于直接复用 React 上游组件。
- 结论：不采用。

### C. Astro + React Islands（采用）

- 优点：默认输出静态 HTML，适配 GitHub Pages；Markdown 内容集合可做 schema 校验；现有 React 展示逻辑和 React 上游组件可渐进迁移；只有显式标记的互动组件才发送客户端 JavaScript。
- 代价：需要一次受控迁移，并重写路由外壳和构建配置。
- 结论：采用。迁移必须保持现有 URL、内容 schema、证据语义和测试覆盖。

## 6. 信息与组件架构

```text
content/**/*.md
      ↓ Astro content collections + schema validation
静态页面、搜索索引、对比数据、图谱 JSON
      ↓
Astro 页面外壳（默认无客户端 JS）
      ├── React Island：首屏互动背景
      ├── React Island：3D 具身单元
      ├── React Island：论文检索控制台
      └── React Island：按需知识图谱
      ↓
GitHub Pages 静态产物
```

模块边界：

- `src/content/`：论文、模型、数据集、项目与路线的唯一事实源。
- `src/content.config.ts`：内容 schema、枚举和跨条目引用约束。
- `src/components/static/`：纯 Astro 展示组件，不发送客户端 JavaScript。
- `src/components/islands/`：需要浏览器状态或图形渲染的 React 组件。
- `src/lib/`：检索、比较、图谱和证据规则，不依赖 UI。
- `public/models/` 与 `public/media/`：只放自有或有明确使用权的优化资产。
- `.github/workflows/`：PR 验证、主分支部署和后续自动研究 PR。

## 7. 视觉系统

视觉主题为“深空具身实验室”，不照搬参考站的具体布局：

- 基础色：近黑蓝背景、冷灰文本、青蓝能量色。
- 语义强调：验证通过用青绿，作者自评用琥珀，待核用中性灰；状态同时显示文字或图标。
- 空间语言：轨道线、坐标刻度、半透明实验面板、局部辉光；避免整页高亮和持续闪烁。
- 字体：中文系统无衬线负责正文，等宽字体负责编号、协议与证据标签。
- 圆角、阴影和发光统一由设计 token 控制，组件不得自行定义一套视觉语言。

## 8. 页面体验

### 8.1 首页

- 首屏包含站点定位、研究主线入口和实时内容计数。
- `GridDistortion` 作为低对比背景，不能影响标题可读性。
- 3D 具身单元作为独立 Island；只在桌面端、可见且设备允许时加载。
- 标题首次进入可使用字符重排，完成后恢复普通可选择文本。
- 下方研究卡片使用光标聚光与轻微景深，不使用大幅旋转。

### 8.2 论文检索

- 现有关键词、方向、标签、年份、来源和证据筛选保持不变。
- 筛选区升级为 Research Console，URL 参数仍是可分享状态。
- 搜索结果动画只作用于新增/移除，不改变阅读顺序。
- 无 JavaScript时仍显示完整论文清单和基础链接。

### 8.3 模型与数据集对比

- 保留字段级来源、单位、证据状态和跨协议禁止排名规则。
- 新增协议一致性锁：只有口径兼容时才显示排序入口。
- 雷达图只展示经过明确定义、单位归一且语义相同的字段；否则使用表格。
- 每个可视字段均能展开来源和缺失原因。

### 8.4 知识图谱

- 页面先输出完整关系清单，再提供“加载交互图谱”按钮。
- Cytoscape 仅在用户请求或组件进入视口后加载。
- 支持按研究方向聚类、节点搜索、邻居高亮和路径回溯。
- 键盘和触屏用户可通过等价列表完成相同导航。

### 8.5 论文阅读页

- 添加阅读进度、粘性章节导航、图表灯箱和证据透镜。
- 证据透镜只改变证据标记的显著程度，不隐藏正文或改写结论。
- Mermaid、公式和图片均提供标题、来源与替代文本。

## 9. 动效与性能策略

动效分三级：

1. CSS/WAAPI：按钮、卡片、标题和滚动进度，优先使用。
2. Canvas：点阵等轻量背景，空闲后停止动画帧。
3. WebGL：图片扭曲和 3D 模型，仅用于首屏焦点，动态导入。

强制降级规则：

- `prefers-reduced-motion: reduce`：关闭字符重排、视差与连续动画，显示静态背景和模型封面。
- 触屏或窄屏：关闭光标追随，3D 模型默认不加载。
- WebGL 创建、模型或纹理加载失败：显示同尺寸静态海报，不阻断页面。
- 页面离屏、标签页隐藏或动画回稳：停止 `requestAnimationFrame`。
- `devicePixelRatio` 上限为 2；所有组件卸载时释放纹理、几何体、监听器和观察器。

性能预算：

- 首页静态内容必须先于互动层可用。
- 首屏非互动 JavaScript目标为 0；首屏互动 Island 的初始 gzip 总量不超过 120 KB，不含按需 Three.js chunk。
- Three.js 和 Cytoscape 不得进入所有页面共享包。
- 移动端首屏不下载 GLB、PBR 纹理或 Cytoscape。
- GitHub Actions 记录构建产物大小，并在超过预算时阻断 PR。

## 10. GitHub-first 工作流

### 10.1 分支和 Pull Request

- `main` 是唯一发布分支，禁止日常直接推送。
- 功能、内容和自动研究结果都通过独立分支与 Pull Request 进入。
- PR 模板要求填写变更类型、来源、证据状态、视觉截图和验证结果。
- `CODEOWNERS` 指定代码、内容和工作流的审核责任。

### 10.2 PR 验证

`verify.yml` 在每个 PR 上执行：

1. 锁文件安装。
2. Markdown schema 与跨引用校验。
3. 单元测试和渲染测试。
4. Astro 生产构建。
5. 链接、可访问性与产物体积检查。
6. 生成可下载的静态预览 artifact；不自动发布到生产地址。

### 10.3 GitHub Pages 发布

`deploy-pages.yml` 只在 `main` 更新后执行：

1. 重复执行关键验证，避免绕过 PR 的提交被发布。
2. 构建静态站。
3. 使用 GitHub Pages 官方 artifact 与 deploy actions 发布。
4. 部署环境命名为 `github-pages`，部署 URL 写入工作流输出。

发布事实必须以 Actions 成功状态和线上 smoke test 为准；本地构建不等于已发布。

### 10.4 分支保护

- 要求通过 Pull Request 合并。
- 要求 `verify` 状态检查通过。
- 要求对话已解决。
- 禁止 force push 和删除 `main`。
- 若账户方案支持，要求至少一次非提交者审核；个人单人仓库无法满足该条件时，保留手动合并门禁并记录为治理限制。

## 11. 自动研究内容流程

阶段三保持以下边界：

```text
定时发现来源
  → 去重与可访问性检查
  → AI 结构化提取
  → schema 校验与证据标注
  → 机器人分支
  → Pull Request
  → 人工审核
  → 合并 main
  → Pages 发布
```

机器人无权直接合并。Secrets 只用于 Actions，不能进入日志、Markdown、静态索引或网页产物。

## 12. 迁移策略

迁移采用“保持内容与 URL、替换运行外壳”的方式：

1. 冻结现有路由、内容 schema 和渲染测试为迁移基线。
2. 建立 Astro 外壳与 GitHub Pages 基础部署，在无动效情况下达到内容等价。
3. 迁移现有搜索、比较和图谱规则，并验证行为一致。
4. 依次接入文字动画、卡片交互、点阵、图片扭曲、3D 模型和 Cytoscape。
5. 每加入一个重型组件都检查移动端、reduced-motion、失败回退和包体积。
6. GitHub Pages 通过线上 smoke 后，再决定是否关闭原 Sites 部署；未获明确授权前不删除旧部署。

## 13. 测试与验收

### 源码层

- 第三方组件有来源、版本、许可证和版权声明。
- 参考站源码和视觉资产未进入仓库。
- Markdown schema、跨引用和证据规则保持一致。

### 构建层

- 类型检查、单元测试、渲染测试、链接检查和 Astro 构建通过。
- GitHub Pages 子路径与自定义域名两种 base 配置都有测试。
- 产物体积不超过预算。

### 浏览器层

- 桌面端验证互动背景、3D 模型、检索、图谱和阅读工具。
- 360 px 宽度无横向溢出，触屏无需 hover 才能获取信息。
- 键盘可达、焦点可见、状态不只依赖颜色。
- reduced-motion、WebGL 失败和资源加载失败都有静态等价视图。
- 控制台无未处理错误，页面切换后无残留监听器或动画循环。

### 部署层

- PR 检查真实通过。
- 合并 `main` 后 Pages workflow 成功。
- 线上首页、论文详情、搜索、比较和图谱入口完成 smoke test。

## 14. 完成定义

只有同时满足以下条件，视觉升级才算完成：

- GitHub 仓库是唯一代码和 Markdown 事实源。
- 所有生产变更经 PR、验证与人工合并进入 `main`。
- GitHub Pages 是已验证的正式发布路径。
- 核心视觉组件来自许可明确的上游或站内独立实现。
- 桌面端具有高辨识度互动体验，移动端保持快速、清晰和完整。
- 证据标注、跨协议比较限制和自动研究人工审核边界未被视觉升级削弱。
